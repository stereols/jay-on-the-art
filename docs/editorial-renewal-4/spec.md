# Jay on Art 브랜드 페이지 편집 리뉴얼 수정 매뉴얼

2026년 10월 14일. 첫 화면의 브랜드·텍스트 위계, 탐색 헤더, POV 영상, 연도별 프로젝트 탐색, Discover와 경력·워크플로우·프로필 내용을 수정한다. [확정 문구](copy.md)가 모든 화면 카피의 기준이다. 본 문서는 구현 전 명세다.

## 최신 지시와 해석

최신 추가 요청으로 Discover는 총 6개이며 Mansion : 3F를 다섯 번째에 유지한다. Reconstruction의 링크는 `https://www.artstation.com/artwork/obaDnW`다. 이전의 개인 작품 순서와 Sketching Ideas 03 포함 지시를 대체한다.

사용자가 뒤에 제공한 전체 문구가 앞의 부분 문구보다 우선한다. 첫 화면의 기존 ‘아트·기획·개발의 언어를 잇는 제작 리더.’는 새 ‘상상한 세계를, 경험할 수 있는 형태로.’로 교체한다. 한 단계 확대라는 시각적 의도는 이 새 헤드라인에 적용한다. 같은 의미의 이전 문구를 추가해 중복시키지 않는다.

‘워드마크를 현재보다 80% 줄이기’는 현재 렌더링 폭의 **20%로 축소**하는 것으로 해석한다. 현재 크기의 80%로 만드는 것과 구분한다. 대상은 홈의 대표 워드마크이며 헤더·푸터·Resume까지 80% 축소하지 않는다. 두 로고의 윤곽 재작도는 모든 사용처에 적용한다.

05의 소속만 `YIGO · Creative Leader`로 표기한다. 02 문장과 다른 정식 소속 표기의 `YIGO.`는 유지한다. 경력에서 회사와 역할 사이의 앞쪽 `·`를 없애고 별도 행으로 배치한다. 회사·연도 사이의 `·`와 05의 `YIGO · Creative Leader`는 확정 카피대로 사용한다. 대표이사 재직 사실은 Resume에 유지하며 메인에는 최신 카피의 Creative Leader를 사용한다.

본 작업 범위는 문서 준비다. 다음 실행 요청의 완료 범위는 로컬 구현과 필요한 화면 확인이다.

## 첫 화면과 디자인 토큰

첫 화면에서 작은 브랜드 서명 → 최효재 → 영문 전문 영역 → 한글 핵심 문장 → 설명의 위계를 만든다. 영문은 산세리프, 모든 화면에서 이탤릭은 사용하지 않는다. 제공한 확정 문구의 순서를 기준으로 한다. ‘JAY ON ART’는 SVG 워드마크의 접근 가능한 이름으로 사용하며 같은 글자를 별도 제목으로 중복 출력하지 않는다.

현재 `.hero .hero-brand`는 데스크톱 `clamp(300px,30vw,450px)`, 모바일 최대 290px다. 현재의 20% 크기로 표시하는 출발안은 데스크톱 60–90px, 모바일 최대 58px다. 실측된 현행 크기에 0.2를 곱해 비교한다. 아래 새 한글 헤드라인과 이름이 첫 화면의 읽기 중심이 된다.

아래 수치는 화면 확인을 위한 출발값이다. 먼저 토큰으로 정의한 뒤 긴 한글 문장의 줄 길이와 화면 크기에 맞춰 조정한다. 홈 로고를 현재의 20% 크기로 표시하는 조건과 색·카피는 확정 기준이다.

첫 화면 한글 헤드라인은 `--ink: #182525`, 설명은 `--text-strong: #293535`를 출발값으로 사용한다. 기존 `--muted: #656565`를 첫 화면 설명에 적용하지 않는다. `.hero-description`의 letter-spacing 상속과 CSS 우선순위를 검사해 다른 한글 본문과 같은 0 자간을 적용한다. 일반 글자에는 강조색을 쓰지 않고 호버·포커스 글자와 밑줄, 비텍스트 그래픽에 `#FF616B`를 사용한다. 기본 미색 `#F6F1E8`과 확보한 왼쪽 여백을 유지한다.

첫 화면의 LinkedIn·ArtStation 등 외부 링크 그룹을 제거한다. Resume는 새 헤더에서 접근하고 프로필·마지막 연결 영역의 링크는 유지한다. 새 전체 문구에 없는 첫 화면 소속·기존 역할 문장은 중복 노출하지 않는다. SCROLL 안내는 유지한다.

### 임시 Font 페이지

헤더 중앙 탐색에 `Font`라는 임시 링크를 추가하고 `font.html`로 연결한다. 기존 링크와 같은 호버 언더라인을 사용한다. 이 페이지는 정적인 디자인 토큰·타이포그래피 참조 페이지다. 직접 수정용 에디터, 저장·조작 UI는 만들지 않는다.

폰트 패밀리와 실제 적용 가능한 굵기, 크기·줄높이·자간, 미색·잉크·강한 설명색·보조색·강조색, 왼쪽 여백·콘텐츠 폭·간격·모서리·링크 호버·포커스를 실제 적용값과 샘플로 보여준다. 가로·세로 워드마크와 투명 배경, 긴 한글 문단, 제목·역할·본문·메타의 사용 예를 포함한다. 작은 화면에서는 읽기 쉬운 한 열 배치와 홈 복귀 링크를 제공한다.

사이트와 Font 페이지는 같은 CSS 토큰 원본을 참조해야 한다. 토큰 예시와 실제 사이트가 다른 값을 사용해서는 안 된다. 필요한 경우 공통 토큰 파일을 분리하고 기존 중복 override를 정리한다. 헤더의 홈 전용 등장 규칙을 Font 페이지에 적용해 탐색을 숨기지 않는다. GitHub Pages의 저장소 경로에서도 상대 링크가 정상 작동해야 한다.

## 가로형과 세로형 워드마크

기준 자산은 `assets/brand/jay-on-art-*-rounded*.svg`다. 가로형·세로형, `currentColor`·밝은 변형을 이 세트에서 관리한다. 페이지 안의 인라인 복제본은 `scripts/sync-wordmarks.mjs`로 같은 원본에 맞춘다. 사용하지 않는 이전 워드마크 파일은 저장소에서 제거했다.

Jay 부분만 기존 시각적 볼드에서 한 단계 가볍게 만든다. 현재 자산은 글자 윤곽 path이므로 `font-weight`를 바꾸는 것만으로 얇아지지 않는다. 윤곽의 두께·카운터를 편집하거나 정확한 원형 글자 자료가 있으면 그 자료를 기준으로 재작도한다. 흰색 stroke로 덮어 얇게 보이게 하는 방식은 투명 구멍을 깨뜨리므로 사용하지 않는다. ‘on Art’까지 같은 비율로 얇게 만들지 않는다.

세로형 y 하단과 h 상단의 정렬, 닷 색 `#FF616B`, 잉크와 밝은 변형, 글자 안쪽·바깥 투명도를 유지한다. 가로 비율을 줄여도 닷은 원형을 유지하며 글자·닷 간격은 새 윤곽에 맞춰 조정한다. 모든 인라인 복제본·헤더·홈·푸터·Resume·Font 페이지를 갱신한다. 미색·어두운 배경·체크무늬에서 비교하고 최종 홈의 작은 표시 크기에서도 ‘Jay on Art’가 인지되는지 확인한다.

## 헤더 등장

헤더 프레임과 바디를 나누는 상시 경계선만 제거한다. 글로벌 페이지 격자나 다른 섹션 구분선을 함께 제거하지 않는다.

홈 첫 화면에서는 헤더를 투명하고 보이지 않는 상태로 시작한다. 00 / POINT OF VIEW가 진입하는 실제 문서 위치에 맞춰 opacity가 0→1, 위치가 약 12px 위→정위치로 부드럽게 나타난다. 출발 구간은 00 상단이 화면 하단 20%에 들어올 때부터 상단 60%까지다. 고정된 scrollY 45px 조건으로 등장시키지 않는다. 최상단으로 되돌아가면 같은 구간에서 자연스럽게 사라진다.

숨겨진 헤더는 클릭·키보드 초점을 가로채지 않는다. 헤더 내부 링크에 키보드 초점이 진입하면 보이도록 하는 접근성 경로를 제공한다. 직접 링크로 00 이후에 진입하거나 새로고침하면 현재 위치에 맞는 상태로 즉시 계산한다. 모션 감소에서는 이동 없이 표시·숨김하고 독립 문서인 Font·Resume에는 기본 표시한다.

## 00 원형에서 확장되는 영상

현재 app.js의 `--pov-inset-x/y`, `--pov-bottom`, `--pov-radius`는 축소 상태를 긴 라운드 바처럼 만든다. 시작 형상은 가로·세로가 같은 약 88–112px의 `#FF616B` 원이며 내부 영상이 보이지 않는다. 텍스트 아래의 자연스러운 위치에서 시작한다.

스크롤이 진행되면 원의 중심을 기준으로 형태가 커지고, 영상은 충분히 커진 뒤 점진적으로 드러난다. 코랄 그래픽→원형으로 마스킹된 영상→큰 영상 프레임→기존 풀스크린 무대로 이어진다. 가장 작은 상태의 영상 노출이나 가로로 찌그러진 캡슐을 없앤다. 모핑의 폭·높이·radius를 함께 조절하거나 clip-path 등 적합한 구현을 선택하되 원형 시작점과 역방향 복귀를 만족시킨다.

원형은 자동 재생 버튼처럼 보이는 불필요한 재생 아이콘을 넣지 않는다. 실제 재생/정지 제어는 영상이 충분히 펼쳐진 시점에 나타난다. 기존 영상 파일, 사용자 제공 영상 표기, 화면 밖 정지, 로딩·재생 실패 시 포스터를 유지한다. 모바일·정적·모션 감소에서는 설명 뒤에 바로 읽을 수 있는 영상 프레임으로 단순화할 수 있다.

숫자 기반 이전 해시는 각 기존 작품을 계속 가리키게 보존하고, 시각적 번호·타일 data-project-index·직접 링크·이전/다음·카메라 순서는 새 순서를 따른다. app.js의 숫자 해시에서 단순히 번호−1을 배열 인덱스로 사용하는 구현을 바꿔 ID→현재 위치로 찾는다. 필요하면 고유 프로젝트 키를 추가한다.

### 우측 연도 그래프

프로젝트가 확대되어 상세 무대에 정착할 때 우측에 얇은 세로 연도축이 나타난다. 미색 공간·잉크 라벨·코랄 진행점으로 전체 테마와 맞춘다. 데스크톱 축의 출발 폭은 80–110px이며 오른쪽 여백 안쪽에 둔다. 대표 이미지의 상세 위치를 기존 약 37vw 시작점에서 중앙 쪽으로 옮기고 폭도 조정해 설명·이미지·연도축이 겹치지 않도록 한다. 단순히 이미지를 왼쪽으로 크게 밀어 설명을 덮지 않는다.

연도축 범위는 2006–2024, 각 프로젝트의 시작 위치를 주요 정착점으로 사용한다. 활성 카드의 시작·종료 기간을 표시하고 중첩 기간도 허용한다. 같은 2006년에 두 카드가 있어도 활성 작품을 구분한다. 카드 안 스크롤을 임의의 실제 날짜나 완료율로 해석하지 않는다. 진행점은 활성 프로젝트 사이를 부드럽게 이동하고 그 진행률은 `worldFrame`과 공유한다. 독립된 또 다른 scroll handler로 상태를 따로 계산하지 않는다.

연도·프로젝트 정착점은 클릭·키보드로 해당 카드에 진입할 수 있고, 현재 프로젝트는 텍스트와 aria-current로도 표시한다. 모바일은 이미지 옆에 축을 억지로 넣지 않고 아래의 간결한 연도 탐색/기간 표기로 배치한다. 정적 모드는 실제 정렬된 프로젝트 목록을 노출한다.

현재 `CARD_SPAN=1.12`를 약 0.85–0.95 화면 높이로 줄이는 것을 출발안으로 삼는다. 첫 마구마구의 이미지 정착→설명 진입은 유지하고 두 번째부터 이미지·설명이 함께 넘어간다. 더 짧은 구간에서도 읽을 위치가 존재하며 자동 시간 재생을 추가하지 않는다. 우측 하단의 `02 / NEXT`는 **NEXT CHAPTER**로 교체하고 클릭하면 남은 프로젝트 전체를 건너뛰어 02로 이동한다. 다음 프로젝트 버튼과 혼동하지 않도록 접근 가능한 이름을 준다.

기존 실제 작품 자산은 해당 작품에 맞춰 유지한다. Discover(06), 카운터, rail 폭·횡이동 거리, 카드별 직접 위치, 이전/다음 경계와 접근성은 새 순서에 맞춰 재계산한다. Marakun 조립 소개를 다시 넣지 않는다.

## 03 같은 무대에서 이어지는 경력

어두운 우주에서 줌아웃하며 ‘상상을 현실의 경험으로.’가 나타난다. 다음 스크롤은 화면을 별도 페이지로 밀어내지 않고 이 제목을 페이드아웃하면서 ‘세계를 만들며 쌓아온 경험.’과 새 경력 영역을 같은 고정 무대에서 페이드인한다. 전경의 이동·새 페이지 경계선·공백 스크린으로 교체를 표현하지 않는다.

공유 무대의 중간 스크롤 구간 약 36–62%를 크로스페이드 출발안으로 잡되 실제 줌아웃·밝아짐·블러 해제와 읽기 시간을 보고 조정한다. 모든 전경은 하나의 공유 진행값을 사용하고 역방향에서 같은 상태로 돌아간다. 제목이 완전히 교체된 뒤 긴 경력 목록은 자연스러운 세로 읽기 흐름으로 빠져나온다. 네 회사 묶음 전체를 작은 고정 화면 안에 압축하지 않는다.

현재 `#threshold`와 `#career`는 별도 섹션, app.js의 `--passage-title`도 진입 제목만 제어한다. 공통 고정 컨테이너/공유 전환 진행을 도입하거나 두 섹션을 같은 무대로 연결한다. 기존 직접 링크 `#career`, 페이지맵의 EXPERIENCE, camera-timeline.js가 측정하는 threshold·career 지점을 새 구조에 맞춘다. 숨겨진 두 제목·경력 링크가 동시에 키보드 초점을 받지 않도록 한다.

경력 카피는 확정 문구의 YIGO. / MORAI / 엔트리브소프트 / 넷마블 외 네 묶음이다. 회사와 연도, 역할, 짧은 설명을 분리해 기존 회사 이름 뒤 `· 역할`과 `/ 대표이사`를 메인 표시에서 제거한다. 더 상세한 사실은 Resume에 보존한다. 글자 크기는 토큰 표처럼 역할·설명·기간까지 각 위계에서 한 단계 확대하며 넷마블 외의 본문을 누락하지 않는다.

## 04와 05 및 마지막 화면

04는 SCAN → FRAME → BUILD → EVALUATE의 네 단계로 교체한다. 기존 SOURCE/NARRATIVE/REVIEW 문구, 이전 단계의 evidence 라벨이나 설명은 새 카피와 맞지 않으면 제거한다. 각 단계의 노드·연결선·도달 상태와 스크롤 반응은 새 제목·문단 길이에 맞춰 배치한다. 새 소개 ‘경험의 구조를 설계해, 실제로 작동하는 형태로 구현합니다.’를 헤드라인 아래에 추가한다. 이 내용은 사용자의 작업 관점이며 실증 결과나 수치를 임의로 덧붙이지 않는다.

05는 확정 카피대로 이름·`YIGO · Creative Leader`·새 리드·두 설명 그룹을 배치한다. ‘YIGO’ 뒤 닷 삭제는 이 소속 행에만 적용한다. 프로필 사진과 임시 상태, 프로필의 외부 링크는 유지한다. 본문 안 ‘현재 YIGO.에서’는 그대로 둔다. 마지막 영문 eyebrow와 ‘함께 만들 다음 경험을 이야기해요.’로 교체하고 연결 링크를 유지한다.

02는 확정 카피를 반영하되 이미 구현한 풀스크린 영상 선행→중앙 제목→프레임 복귀 흐름을 사용한다. ‘기억을 콘텐츠로, 경험을 제품으로.’를 영상과 설명부에 중복 헤드라인으로 쌓지 않는다.

카드 속도·경력 무대·문단 길이가 바뀌므로 카메라는 실제 새 섹션 위치에서 경로를 다시 측정한다. 첫 화면·Discover 전후·최하단의 정·역방향 연결, 마우스 반응·블러·밝기·회전의 연속성을 유지한다. 기존 최하단 구도를 임의의 새 초기 구도로 리셋하지 않는다.

완료 확인은 다음 변경을 실화면에서 판단한다. 필요한 빌드·동작 확인을 수행하고 실패한 부분을 수정하되, 이미 통과한 범위를 매 단계마다 전체 반복하지 않는다.
