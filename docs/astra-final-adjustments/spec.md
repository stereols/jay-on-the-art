# Jay on Art 브랜드 페이지 최종 수정 명세

2026년 10월 14일. 로고의 윤곽과 투명도, 텍스트 색, 영상 진입, 작품 탐색, 우주 카메라 연결을 수정한다. 이 명세는 구현 전 기준이며, 이후 실행 요청에서 Astra가 구현·검수할 범위를 정의한다.

## 적용 우선순위

최신 사용자 요청과 이 명세를 우선한다. 이전 문서의 Marakun 전체 조립 탐색을 Discover 첫 화면에 넣는 지시, 기본 텍스트에 강조색을 적용하는 지시, 기존 SVG 사용 완료 기록은 이번 요청으로 대체된다. 코드의 기존 변경을 먼저 확인하고 필요한 부분을 이어서 고친다.

브랜드 고유명, 한글 헤드라인, 산세리프와 이탤릭 금지, 두 배로 확대한 주요 왼쪽 여백, Discover의 큰 영문 제목, 회사 프로젝트 10개·개인 작품 6개의 사실·순서는 유지한다. 이전 구현의 검수 통과 기록을 이번 변경의 검수로 사용하지 않는다.

## 로고 윤곽과 투명도

이전 워드마크 참고 원본은 references/previous-wordmark-01.png와 references/previous-wordmark-02.png다. 사용자 제공 원본은 내용 변경 없이 보존한다.

- 가로형은 이미지 01의 글자 모양과 자간, 심벌·보조 라인의 상대 크기와 위치를 기준으로 삼는다.
- 세로형은 이미지 02의 각 글자 크기와 가로 배치를 유지한다. Jay on Art를 조금 위로, 아래 문장을 조금 아래로 이동해 위쪽 y 윤곽의 최하단과 아래쪽 h 윤곽의 최상단이 같은 수평선에 놓이게 한다. 실제 원본 픽셀에서 측정하며, 두 줄 전체를 임의로 늘이거나 줄이지 않는다.
- 폰트 이름을 추정해 비슷한 글자를 다시 입력하지 않는다. 제공 이미지의 윤곽을 벡터로 추출·정리하거나, 정확히 일치하는 원본 글자 윤곽을 확보해 path 기반 SVG로 만든다. 기존 textLength와 spacingAndGlyphs로 폭을 강제한 SVG는 기준 자산에서 제외한다.
- 글자 내부의 구멍과 윤곽 바깥은 투명하다. SVG에 흰 사각형이나 래스터 이미지 전체를 넣지 않는다. a·o·e 등 내부 공간도 배경이 관통하게 한다. 단색 잉크 #182525와 닷 #FF616B를 사용한다.
- SVG는 실제 윤곽을 기준으로 viewBox와 여백을 일관되게 정한다. 렌더링은 height:auto와 균일한 배율을 사용하고 CSS의 비균일 scale, 글자 폭 강제 조정, 잘못된 고정 가로·세로 크기를 제거한다.
- 새로운 버전 파일을 만들고 사이트의 모든 인라인 복제본 또는 참조를 갱신한다. 헤더, 첫 화면, 푸터, Resume를 확인한다. 이전 원본을 덮어쓰는 대신 교체 전 버전을 보존한다.

현재 assets/brand/의 SVG는 text와 circle로 구성됐으며 배경 사각형이 없다. 보이는 흰 패널은 brand-system.css의 .dark-chapter .topbar .brand 배경에서도 발생한다. 이 패널을 제거한다. 어두운 장면에는 같은 윤곽의 밝은 잉크 버전을 사용할 수 있으며 닷은 #FF616B를 유지한다. 일반 텍스트의 호버 규칙을 로고 전체에 적용하지 않는다.

벡터 추출 품질이 충분하지 않으면 동일 윤곽과 정렬을 가진 고해상도 투명 PNG를 대체 자산으로 준비할 수 있다. 이 경우 SVG인 것처럼 설명하지 않고 형식과 교체 이유를 보고한다. 우선 목표는 윤곽 path SVG다.

검수는 체크무늬, 미색, 어두운 배경 위에서 한다. 원본과 새 자산을 같은 배율로 겹쳐 윤곽·상대 크기를 비교한다. 세로형의 y 하단과 h 상단 정렬 오차는 원본 픽셀 기준 약 1px 이내를 목표로 한다. 화면 크기가 바뀌어도 비율이 동일해야 한다.

## 색과 텍스트 링크

--primary는 #FF616B다. 평상시 본문, 헤드라인 span, 보조 설명, eyebrow, 선택된 단계의 글자에는 강조색이나 기존 진한 로즈 #9e3441을 적용하지 않는다. 잉크색과 중립 회색을 사용한다. 링크에 포인터를 올리면 글자와 나타나는 언더라인에 정확히 #FF616B가 적용된다. 가까운 로즈색으로 대체하지 않는다.

헤더의 Resume 링크는 기존 버튼 예외다. 그 외 텍스트형 탐색·소셜·CTA 링크의 바·알약 배경과 상시 테두리를 제거하고 호버 언더라인으로 통일한다. 키보드 포커스에도 식별 가능한 표시를 제공한다. 작품 이미지·카드 자체, 영상 재생, 페이지맵 열기, 이전·다음 같은 실제 조작 버튼을 텍스트 링크로 바꿀 필요는 없다. 작품 카드 안의 텍스트 링크에는 같은 호버 규칙을 적용한다.

로고 닷, 진행선과 비텍스트 상태 표시는 강조색을 사용할 수 있다. 평상시 일반 텍스트의 computed color와 링크 hover color를 분리해 검사한다.

## 배경과 보조 설명 크기

주 배경은 따뜻한 미색으로 바꾼다. 출발 색은 #F6F1E8을 권장하며 최종 색은 밝은 우주의 재질·대비를 보고 조정할 수 있다. CSS의 paper·body·wash·fallback, Three.js daySky·clear color·fog, 헤더와 섹션의 밝은 패널을 같은 기준으로 맞춘다. 어두운 전환과 영상 자체를 미색으로 덮지 않는다.

헤드라인과 함께 등장하는 보조 설명 그룹은 두 단계 확대한다. 출발 크기는 데스크톱 15→18→22px, 모바일 14→16→18px다. 기존 12px 보조 문구는 14→16px처럼 동일 위계의 두 단계를 적용한다. 제목 크기는 이미 정한 위계를 유지한다.

대상은 hero의 소개, POV 설명, 01 소개, Discover 제목 옆 설명, 경력 제목 옆 설명, 해당되는 프로필·다른 장면의 소개 그룹이다. 프로젝트 회사·기간, 이미지 고지, 이력 상세 본문, 버튼·메타데이터까지 일괄 확대하지 않는다. 줄 길이와 모바일 줄바꿈을 보고 실제 값을 조정하되 이전 크기보다 두 단계 커졌다는 위계를 확보한다.

## 02 영상 중심 진입

[Apple Vision Pro](https://www.apple.com/apple-vision-pro/)를 실제 브라우저에서 스크롤해 영상의 고정, 전경 텍스트, 프레임으로 복귀하는 전환을 확인한다. 정적 웹 문서 조회만으로 렌더러나 세부 타이밍을 확정하지 않는다. Apple의 코드·영상·문구를 복사하지 않고 사용자가 지정한 동작을 구현한다.

최종 순서는 다음과 같다.

1. 02에 들어오면 기존 임시 영상이 먼저 전체 화면을 채운다. 제목이나 삭제 대상 작은 텍스트가 영상보다 앞서지 않는다.
2. 조금 더 스크롤하면 ‘기억을 콘텐츠로, 경험을 제품으로.’가 아래에서 부드럽게 올라와 화면 중앙에 정착한다. 영상과 충분한 대비를 확보한다.
3. 읽는 구간 뒤에 영상이 현재 영상 슬롯의 프레임 크기·비율로 자연스럽게 돌아온다. 같은 영상 요소의 확대·축소로 연결하는 것이 권장된다.
4. 고정 구간이 끝나면 기존 YIGO./Aelin 기획·개발 설명을 따라 정상적인 세로 문서 흐름으로 빠져나온다. 역방향도 같은 순서를 거슬러 간다.

삭제: IN DEVELOPMENT, YIGO. / DIGITAL CONTENT PLATFORM, 별도 Aelin 소제목, 소제목 옆 ‘기억을 콘텐츠로. 경험을 제품으로.’. 중심 헤드라인은 유지하고 중복 표시를 만들지 않는다. 02 영문 장면 라벨은 유지한다.

임시 영상·Aelin 실제 화면이 아님 고지는 사용자에게 보이는 적절한 위치에 유지한다. 로딩 전 포스터, 실제 재생, 재생 실패 안내, 화면 밖 정지, 수동 재생·정지를 보존한다. 모바일·모션 감소에서는 제목과 영상이 읽히는 세로 대체 흐름을 제공한다.

## Discover 첫 장면 제거

.discover-intro와 Marakun 조립 과정의 첫 진입 장면을 통째로 제거한다. 네 단계 조립 UI와 축소 전환도 이 장면과 함께 제거한다. 개인 작품 6개는 첫 Marakun Modular Village 카드부터 바로 기존 횡이동으로 시작한다. 작품 카드·원본 링크·제작 범위 고지는 보존한다.

app.js의 Marakun 요소 초기화, 단계 이벤트, #marakun-explorer 처리와 discover.js의 intro 의존성을 함께 정리한다. 제거된 DOM을 찾다가 전체 앱 초기화가 중단돼서는 안 된다. 이전 #marakun-explorer 링크는 Discover의 첫 카드로 연결하는 대체 경로를 둘 수 있다. Discover 높이·진행률·이전/다음·키보드 탐색·페이지맵을 새 구간에 맞춘다.

## 카메라 연결

현재 코드의 연결 위험은 app.js의 장면 선택과 진행률 계산, cosmos.js의 장면별 route 경계에 있다. 일반 local은 section height에서 viewport height를 뺀 구간으로 계산된다. 첫 화면의 높이가 viewport와 같거나 마지막 장면이 viewport보다 짧으면 분모가 1px이 되어 시작·끝 좌표가 거의 한 번에 바뀔 수 있다. 이는 확인된 계산 구조에 따른 원인 후보이며, 실제 스크롤 영상과 데이터로 확인한다.

카메라의 진행 구간과 DOM 고정 구간을 구분한다. 문서의 의미 있는 스크롤 지점으로 하나의 절대 카메라 진행을 정의하고 인접 구간의 위치, look-at, 회전·행성 phase를 일치시킨다. viewport보다 작은 장면에서도 경로를 1px 안에 완주시키지 않는다. 마우스 반응은 이 절대 경로 위의 작은 추가 이동으로 유지한다.

- 첫 화면의 기존 시작 구도를 유지하면서 아래로 이동할 때 첫 행성이 자연스럽게 이어진다.
- 참여 프로젝트→02→Discover→경력 전환의 경계를 새 높이와 순서에 맞춰 재설정한다. Discover 삭제된 intro 길이를 옛 카메라 시간표에 남기지 않는다.
- 마지막 화면은 현재 가장 하단 구도를 끝점으로 고정한다. 그 구도에서 위로 되돌아갈 때 앞 장면으로 연속적으로 이어져야 한다. 마지막 장면을 다른 초기 구도로 재설정하지 않는다.
- night·wash·blur도 카메라와 같은 지점에서 연결한다. 순간적인 밝기·회전·초점 점프를 카메라 보간으로 숨기지 않는다.

현재 마지막 pose의 기준은 cosmos.js의 links: camera [.2,-5.5,21], target [1,-5,-3], orbit phase 4.6이다. 구현 착수 때 코드가 달라졌으면 실제 최하단 화면을 기준으로 다시 확인한다.

| Discover | 조립 첫 장면 제거, 6개 카드·원본 링크·탐색 정상 |
| 03·04 | 지정 텍스트·중앙 장식 제거, YIGO. 최상단, 빠른 줌아웃·블러 해제 |
| 카메라 | 첫 화면·Discover 전후·마지막 화면의 양방향 경계에서 좌표·초점·회전·밝기 점프 없음 |
| 대체 흐름 | 모바일, 모션 감소, 정적·WebGL 대체, 새로고침·직접 링크 정상 |

실제 데스크톱·모바일 브라우저에서 바뀐 흐름을 확인하고, 카메라 경계는 전후 연속 캡처나 짧은 녹화로 확인한다. 단순 화면 한 장이나 문법 검사만으로 움직임의 연속성을 통과 처리하지 않는다. 필요 빌드·검증을 수행하고 발견한 문제를 수정한 뒤 로컬 미리보기와 근거를 전달한다. 커밋·push는 이번 로컬 구현의 자동 완료 단계에 포함하지 않는다.

## 공식 워크플로우 근거

[OpenAI의 Astra 글](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)은 필요한 자료만 문맥에 따라 읽는 구조와 명확한 완료 경계를 권장한다. [GPT-6 prompting best practices](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)는 사용자 지시의 우선순위, 승인된 작업의 완수, 변경에 맞는 검증 범위를 다룬다. 이 명세의 웹 연출·로고 좌표·색·크기 선택은 사용자의 요구를 정리한 프로젝트 기준이다.
